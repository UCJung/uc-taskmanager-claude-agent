3. **Phase 4.3: Committer FAIL Retry Logic**
   - Failure detection: progress.md not found / status not COMPLETED / no files changed
   - Re-dispatch builder with existing progress.md for resumption
   - Maximum retries: 2 additional attempts (total 3 tries)
   - After 3 failures: mark TASK as FAILED, halt pipeline
   - Log retry attempts in PROGRESS.md

Additionally updated the XML Schema Reference section and added new Context-Handoff Policy Reference section pointing to `agents/context-policy.md`.

## Why

Scheduler needs explicit rules for:
1. Compressing context within a TASK's pipeline stages (builder→verifier→committer)
2. Passing context between dependent TASKs based on distance (direct vs. 2-step vs. 3+)
3. Handling committer failures gracefully through builder resumption

These rules reduce token waste by applying sliding window compression while maintaining critical context, and enable graceful failure recovery through progress.md checkpoints.

## Caution

The TASK-to-TASK context-handoff dependency passing (Phase 4.2) requires that result.md files generated by committer MUST include a "Context Handoff" section with both Builder (SUMMARY) and Verifier (FULL) contexts. This is verified in WORK-07-TASK-03 (committer.md modifications).

Retry logic (Phase 4.3) assumes that builder.md will respect the progress.md checkpoint and resume from the last recorded state, not restart from scratch. This is implemented in WORK-07-TASK-02.
